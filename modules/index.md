# Module Index

Each module is a thinking lens, not a personality.

Use at most 2-3 modules per session.

| Module | Primary Use | Kernel Question |
|---|---|---|
| Ritchie / Thompson | Minimal abstractions | What is the smallest useful primitive? |
| Hopper | Translation | How does this become usable by humans? |
| Hamilton | Correctness | What must not fail? |
| Knuth | Rigor | What is the precise structure of the problem? |
| Dijkstra | Simplicity | What complexity can be deleted? |
| Liskov | Boundaries | What contract must remain stable? |
| Kay | Future prototype | What future becomes obvious if we prototype it? |
| Carmack | Implementation density | What can be measured and simplified today? |
| Torvalds | Review and scale | What would break under real collaboration? |
| Lamport | Distributed reasoning | What are the order, state, and agreement assumptions? |
| Beck / Fowler | Change | What test or refactor makes the next change easier? |
| Future Engineer | AI orchestration | What can be delegated, verified, and closed safely? |
